# Clover anti-slop audit 001

Date: 2026-11-03
Mode: AFTER (audit first, fix only what is approved)
Scope: the UI shipped in releases v1.0.147 to v1.0.161, plus the shared helpers
those changes depend on (`valueBadge`, the filter-pill family, `.badge` tones).
Not a full-app audit: Clover predates antislop, so anything outside those
releases is listed only where a new feature sits directly on top of it.

Evidence: WCAG ratios computed with the formula in `antislop-human` and
cross-checked against `contrast-check.py` (identical results). Box sizes and
keyboard wiring read from `styles.css` / `app.js`. No browser run: see finding 10.

Priority follows the rule tier. HIGH = Hard Gate (absolute), MEDIUM =
Purpose-Gate (technique allowed, reason required), LOW = Quality Locks.

---

## HIGH (Hard Gate)

### 1. Filter pills cannot be used without a mouse (R-32)

Six pill helpers attach `click` to a `<span>`: `valueBadge` (accounts + subs,
including the new CD-timeline owner pill), `expenseFilterBadge`,
`settleFilterBadge` (Found via), `subsFilterBadge`, `incomeCatBadge` (Income
Category), `yoyFilterBadge`. None sets `tabindex`, `role="button"`, or a
`keydown` handler, so none is reachable by Tab or operable by Enter/Space, and
none can show a focus ring. Filtering by owner, category, source, paid-from or
institution is mouse-only.

Fix: render them as `<button type="button">`, or add `tabindex="0"`,
`role="button"` and Enter/Space handling, plus a `:focus-visible` style.

### 2. Generated pill shades 5 and 6 fail AA (R-25)

`valueBadge` shades each distinct value `L = 90 - (index % 6) * 6`. The 5th and
6th distinct value in a column fall below 4.5:1 against the fixed
`hsl(hue, 55%, 24%)` text:

| Column | shade 4 (L=66) | shade 5 (L=60) |
|---|---|---|
| owner (hue 275) | 4.37 FAIL | 3.47 FAIL |
| type (145) | 4.15 FAIL | 3.72 FAIL |
| institution (215) | 4.50 FAIL | 3.65 FAIL |
| beneficiaries (25) | 4.42 FAIL | 3.72 FAIL |

Shades 0 to 3 pass. This bites as soon as a column has five or more distinct
values, which institution and owner realistically reach. The pills are 11px
(10px for `.cdtl-owner`), so the 4.5:1 normal-text bar applies, not 3:1.

Fix: darken the text as lightness drops (compute per shade), or stop the ramp
at L=72 and vary hue instead of only lightness.

### 3. Taxable "Unknown" badge fails both bars (R-25)

`.badge.amber` is `#d97706` on `#fdf0dd` = **2.83:1**, failing normal (4.5) and
large (3.0). It is the value that most needs to be noticed, and it is the least
readable thing on the Income list. Same tone is used app-wide for warning pills.

### 4. Two more badge tones sit just under AA (R-25)

- `.badge.green` (Taxable = Yes): `#15803d` on `#e6f6ec` = 4.48:1
- `.badge.red`: `#dc2626` on `#fdeaea` = 4.17:1

Both read as fine and both miss 4.5:1.

### 5. Bulk bar text and its Remove button fail AA (R-25)

On the `.bulk-bar` accent-soft background (`#e6f6ec`):

- `.bulk-count` ("N selected"): `#15803d` = 4.48:1
- `.btn-ghost.danger` ("Remove selected", added v1.0.160): `#dc2626` = 4.31:1

The same danger color passes on white (4.83:1); it only fails on the tinted bar.

### 6. "Notes" button with a note fails AA (R-25)

`.icon-btn.has-note` (v1.0.152) is `#16a34a` on white = **3.30:1**. The accent
green was used as a text color, where it needs 4.5:1; `--accent-hover` (#15803d)
would still only reach 4.48:1, so this needs a darker green, not a swap.

### 7. Tap targets under 44px, with no spacing (R-03)

Measured heights of things built to be clicked:

| Element | Size |
|---|---|
| `.cdtl-owner` (owner pill) | ~16px |
| `.badge` / `.val-badge` (all filter pills) | ~20px |
| `.sel-cell input` (bulk checkboxes, v1.0.160) | 15 x 15px |
| `.dash-nav-btn` (month navigator, v1.0.147) | 26 x 26px |
| `.icon-btn` (Edit / Notes / Duplicate / Remove) | 28px |

All are under the 44px minimum, and the row-action buttons sit directly
adjacent, so on a phone a thumb cannot reliably pick one. The owner pill is the
worst: it is both the smallest and newly promoted to the one detail kept on
mobile.

### 8. Component boundaries under the 3:1 non-text bar (R-25)

- `.bulk-bar` border `#cde9d6` on page `#f4f7f4` = 1.20:1
- `.nav-sub` left rule `#e4eae5` on sidebar white = 1.22:1 (the CD Ladder indent cue)
- `.dash-nav-btn` border `#d3dcd5` on white = 1.40:1

The bulk bar is a mode indicator ("you have rows selected"), so its edge
carrying no contrast matters more than the others.

### 9. Em dashes in UI copy (R-02)

10 of 11 sampled strings I wrote this session contain `—`: the linked-income
banner, the owner-pill tooltip, the bulk-delete warnings, the Found via hint,
the month-navigator and CD-renewal field hints, the search empty state, the
matured-CD email setting.

Caveat worth a decision rather than a blind sweep: the app contains **642** em
dashes and they are the long-standing voice of every tooltip and Help point in
Clover. Under R-37 that makes this owner direction colliding with a Hard Gate
rule, so it is yours to call: keep the house voice as a recorded override, fix
only the strings added in these releases, or convert app-wide.

### 10. Shipped without running the app (R-35)

None of v1.0.147 to v1.0.161 was verified in a browser. The local preview is
UNC-blocked, so verification was `node --check` plus Node simulations of the
logic. Those caught real defects, but they cannot see contrast, focus order,
overflow, or whether a pill is actually clickable. No recorded click-through
exists for any of these releases.

Fix: verify against the live site in the Personal Chrome profile (it is already
signed in), clicking each new control and checking the phone width, then record
the result element by element.

### 11. The mobile rule hides text by zeroing it (R-03)

v1.0.161 changed the phone breakpoint to `.cdtl-name-2 { font-size: 0 }` with
the owner pill re-set to 10px. It hides the institution and status by shrinking
them to nothing rather than reflowing, which is an override patch rather than a
designed mobile state, and it leaves a 16px tap target as the only control on
that line.

## MEDIUM (Purpose-Gate)

### 12. Emoji used as decoration in UI copy (R-04)

Added this session: the memo glyph on the "Notes" row button and the scales
glyph opening the linked-income banner. Clover's nav glyphs are a long-standing
identity motif and are not in question; these two are new decoration inside
copy, where the label already carries the meaning.

### 13. Taxable renders a pill for a non-state (R-09)

Every Income row with the Taxable column on gets a badge, including "Unknown",
which is the absence of a decision. A pill on every row spends the eye's
attention without marking anything. Either write the reason (amber is a
to-do marker) or show a pill only for Yes/No and leave Unknown as plain text.

## LOW (Quality Locks)

### 14. New colors have no written reason (R-31)

Teal for "Paid from", purple for "Source", amber for Taxable "Unknown" were
chosen so the columns would look distinct from each other, not against a stated
hierarchy. R-31 wants one line per decision, and these have none.

### 15. Active palette on one table has grown past the cap (R-29)

The Expenses list now shows type (blue-grey), purple, teal and neutral pills
side by side; Income adds green/amber/type for Taxable; the timeline adds four
generated hue families. That is well past 2 to 3 cores plus one accent on a
single screen, with no written system saying which hue means what.

---

## Not findings

- Row action buttons (`Edit`, `Notes`, `Duplicate`, `Remove`) are real
  `<button>` elements and keep the browser focus ring: keyboard-reachable
  (R-32 passes for these; only the pills fail).
- `outline: none` appears four times and every one replaces the ring with a
  visible `box-shadow` focus style (R-32 compliant).
- Empty, loading and error states exist on the lists touched here, including the
  new search empty state with a Clear action (R-27).
- Clover is light-only by design, so there is no second theme to break (R-34).
- Bulk delete confirms first and names its two consequences, so the destructive
  path is not a dead or silent control (R-26).
